# Roadmap

This is a new project, not an established widely adopted service. Priorities should follow feedback from actual maintainers.

## v0.1 — implemented

- Read-only issue, PR, and release collection with pagination and visible truncation.
- Explicit UTC activity windows and separate current-backlog metrics.
- English/Chinese Markdown, JSON output, offline replay, bot filtering.
- Unit tests, CI, and a read-only report workflow.

## Candidate next steps — not yet implemented

- ETag-based caching to reduce repeated API requests.
- Configuration files for multi-repository teams.
- Review/comment timeline support for meaningful response-time measurements.
- Incremental event archives to reconstruct historical backlog.
- GitHub Enterprise Server support with credential-origin protections.
- Distribution through a package registry after real user feedback and release hardening.

## Establishing real value

Use this tool on repositories you maintain, fix problems found in real runs, document concrete time saved, and invite feedback without mass messaging. Publish release notes for real changes. External adoption and sustained maintainer work must develop organically; they cannot be generated by adding project files.
